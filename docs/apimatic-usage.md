# APIMatic usage

Record of how the [APIMatic](https://www.apimatic.io/) PayPal Context Plugin and other APIMatic tooling were used while building Niryat. It is evidence for the APIMatic sponsor prize ([PLAN §12](PLAN.md#12-sponsor-tools)), so add an entry in the same task whenever an APIMatic tool is used ([AGENTS.md](../AGENTS.md)).

Each entry gives the date, the tool, its purpose and the outcome. Record what the tool actually changed or prevented, not just that it was opened.

## Summary for reviewers

Niryat reads a freelancer's PayPal ledger (captures, transaction search, refunds) through the APIMatic-generated PayPal Server SDK for TypeScript, `@paypal/paypal-server-sdk` 2.5.0. We wrote that adapter in Claude Code with the Context Plugin's `paypal:typescript-*` skills loaded. The skills mattered most where the SDK's types say nothing. Each point below is in shipped code:

| What the plugin told us                                                                                                         | What we did                                                                                                                                                                                                                                                                                         | Where                                                                |
| ------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| A client built without a timeout waits forever (`-configuration-resilience`).                                                   | Set a 30-second timeout.                                                                                                                                                                                                                                                                            | [sdk/index.ts:174](../packages/paypal/src/sdk/index.ts#L174)         |
| A rejected token provider affects the whole client (`-authentication`).                                                         | Confirmed in the installed SDK that the OAuth layer caches a rejected token promise, so one failed refresh broke the client for good. `ledgerTokenProvider` now returns an expired token on failure. The current request stops before it reaches the network, and the next one authenticates again. | [sdk/index.ts:152](../packages/paypal/src/sdk/index.ts#L152)         |
| The test seam is a stub adapter passed through `unstable_httpClientOptions`, and the SDK ships no mocks (`-testing`).           | Tests run the real SDK `Client` with an in-process transport, including a regression test that recovers on the same client after missing and expired tokens. They make no PayPal calls and use no SDK mocks.                                                                                        | [sdk/index.test.ts:63](../packages/paypal/src/sdk/index.test.ts#L63) |
| The status code is on `ApiError.statusCode`, and `result` can be undefined on a bare `ApiError` (`-error-handling`).            | Return `null` only on a 404. Other errors become a sanitized `PayPalApiError`: the error name is checked with zod, and no PayPal payload leaks.                                                                                                                                                     | [sdk/index.ts:191](../packages/paypal/src/sdk/index.ts#L191)         |
| Controllers are constructed, not accessed from the client. Models are camelCase on `.result` (`-calling-endpoints`, `-models`). | Built `PaymentsController` and `TransactionSearchController` once per client. Each response is validated with zod before mapping.                                                                                                                                                                   | [sdk/index.ts](../packages/paypal/src/sdk/index.ts)                  |
| Token lifecycle guidance, read before the SDK was installed (`-authentication`).                                                | The hand-written REST client for Invoicing and Disputes caches tokens and refreshes them lazily before expiry.                                                                                                                                                                                      | [rest/index.ts:114](../packages/paypal/src/rest/index.ts#L114)       |

**Scope, stated plainly:** the Server SDK has no Invoicing or Disputes support, so those stay on REST through `fetch`. The plugin covers the SDK side only. SDK refunds run only after the user approves them in Niryat's approval queue. The plugin shaped how we wrote the code; it never called PayPal.
